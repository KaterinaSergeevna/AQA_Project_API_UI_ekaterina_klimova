# 🚀 Модульный фреймворк автоматизации тестирования для интернет-магазина MX.by

## 📌 Описание проекта
Данный проект представляет собой высокоуровневый автоматизированный фреймворк для сквозного тестирования функционала интернет-магазина умной техники `mx.by`. Архитектура спроектирована на языке **Java 21** с использованием подходов **POM (Page Object Model)** и **BDD (Behavior-Driven Development)** в соответствии со стандартами проектирования тестовых систем **ISTQB** и принципами чистого кода **SOLID**.

## 🛠 Технологический стек
* **Язык программирования:** Java 21
* **Тестовая платформа:** JUnit 5 (Platform Engine)
* **Автоматизация UI:** Selenium WebDriver (v4.41.0)
* **Поведенческий подход (BDD):** Cucumber JVM (v7.17.0)
* **Автоматизация API:** Rest-Assured (v6.0.0)
* **Управление зависимостями:** Maven
* **Тестовая отчетность:** Allure Framework (v2.28.0)
* **Логирование:** Log4j2

## 📐 Архитектура проекта и паттерны проектирования
Фреймворк разделен на независимые архитектурные слои согласно принципу **Single Responsibility (SRP)**:
1. **Слой управления сессией браузера (`by.mx.ui.driver`):**
   * **Singleton Pattern (`Driver.java`)** — гарантирует существование строго одного инстанса браузера на протяжении теста, защищая систему от утечек памяти.
   * **Factory Method Pattern (`DriverFactory.java`)** — изолирует и инкапсулирует логику конфигурирования и инициализации инстансов веб-драйвера.
2. **Инфраструктурный слой страниц (`by.mx.ui.page`):**
   * `BasePage.java` — аккумулирует универсальные обертки над явными ожиданиями (`WebDriverWait`) для безопасного и стабильного взаимодействия с элементами (`clickSecurely`, `sendKeysSecurely`, `getInputValueSecurely`). Исключает дублирование кода и хрупкость тестов.
3. **Бизнес-слой страниц (`by.mx.ui.page`):**
   * `SearchPage.java` — инкапсулирует локаторы (XPath/CSS) и предоставляет тестам верхнеуровневые бизнес-методы взаимодействия, названные по строгому стандарту конвенции именования (*Действие + ЦелевойОбъект*).

## 🧪 Тестовое покрытие

### 🌐 UI Тестирование (`SearchTest`)
* Позитивные сценарии поиска существующих товаров.
* Негативные проверки корректности отображения заглушек при пустом ответе.
* Комплексный параметризованный фильтр цен с динамическим парсингом строк с UI и строгой математической валидацией диапазона типов `double`.
* **Тест безопасности (Security Testing):** Отправка боевого SQL-пейлоада тавтологии (`смартфон' OR 1=1 --`) для валидации корректности экранирования и параметризации запросов бэкендом (контроль отсутствия уязвимостей по спецификации OWASP Top 10).

### 🥒 Поведенческое тестирование (BDD / Cucumber)
* Сценарии в каталоге `src/test/resources/features` описаны на международном синтаксисе **Gherkin (Given-When-Then)** с использованием выражений Cucumber Expressions для гибкой параметризации тестов. Шаги полностью связаны со слоем Page Object через раннер `RunBddTest.java`.

### 📡 API Тестирование (`AuthFormTest`)
* Тесты интеграции и валидации бэкенд-эндпоинтов авторизации, использующие фреймворк Rest-Assured.

## 📊 Генерация тестовой отчетности (Allure Report)
Фреймворк интегрирован с плагином `allure-maven`. Отчеты включают в себя пошаговую детализацию прохождения как классических JUnit тестов, так и BDD сценариев (с разбиением по шагам Given-When-Then) и автоматически подгружают логи системы.

## 🚀 Команды для запуска

Запуск всех тестов проекта (UI, API, BDD) и автоматическая сборка результатов Allure:
```bash
mvn clean test
```
